# 项目说明

## 背景

校园里经常出现“人在上课，快递到了驿站”的情况。这个项目想解决的就是代取需求：需要取件的人在平台上发布订单，顺路的骑手接单，取件后送到指定位置，确认签收后完成结算。

项目按校园场景做了简化，没有接真实支付、短信和地图。系统包含浏览器工作台、HTTP 接口、MariaDB 数据库和哈希存证链，打开页面就能完成从发布到评价的完整流程。

## 角色

| 角色 | 能做什么 |
| --- | --- |
| 学生 | 注册、登录、发布订单、查看自己的订单、取消、签收、评价、充值、查钱包和流水 |
| 骑手 | 登录、查看待接单列表、接单、取件、送达、查看自己的订单和收入流水 |
| 管理员 | 查看全量订单、按状态筛选、查看订单统计 |

## 核心功能

### 浏览器工作台

前端是 `web/` 下的原生 HTML、CSS 和 JavaScript，由同一个 Python 服务托管，不依赖 Node.js 和前端构建工具。

- 登录页提供学生、骑手、管理员三个演示入口；
- 学生工作台包含我的订单、发布代取、钱包、信用四个页签；
- 骑手工作台包含可接订单、我的配送、钱包、信用；
- 管理员工作台包含数据概览和全部订单；
- 订单详情用抽屉展示状态进度、操作按钮、哈希时间线和存证校验结果；
- 页面通过 `fetch` 调用 `/api/...`，登录 token 存在 `localStorage`，请求时放到 `Authorization` 头。

### 账号

- 手机号注册，注册后自动成为学生；
- 登录返回 Bearer Token，有效期 2 小时；
- 每次请求通过 `Authorization: Bearer <token>` 识别用户；
- 用户资料包含角色、信用分和钱包余额。

### 订单

订单从发布到完成经过 6 个状态：

```
pending → taken → delivering → delivered → signed
   └── cancelled
```

- 学生发布订单时填写标题、取件点、送达点、跑腿费和超时时间；
- 骑手只能接 `pending` 状态且不是自己发布的订单；
- 骑手接单后，只有该骑手能取件和送达；
- 学生只能签收自己发布的订单，签收时从钱包扣跑腿费，骑手钱包增加同样金额；
- 签收后学生可以评价一次，评分 1–5 星；
- 待接单状态下学生可以取消。

### 钱包与流水

- 钱包余额以整数分存储；
- 发布订单时校验余额，签收时正式扣款；
- 每次充值、支付、骑手收入都写一条 `flows` 记录；
- 流水可以通过类型过滤：`recharge`、`order_pay`、`order_income`。

### 信用分

- 初始信用分 100；
- 评价 4–5 星加 1 分，1–2 星扣 1 分，3 星不变；
- 每次变动写 `credit_logs`，记录原因和关联订单号。

### 存证

订单每次状态变化写一条存证：

```
record_hash = sha256(prev_hash | order_id | event | title | status)
```

- 第一条记录的 `prev_hash` 是 64 个 `0`；
- 后面的记录指向前一条的 `record_hash`；
- `GET /api/orders/{id}/timeline` 返回完整时间线；
- `GET /api/orders/{id}/verify` 重算整条链，返回是否有效和断点位置。

## 业务规则

| 规则 | 说明 |
| --- | --- |
| 手机号 | 11 位，`1[3-9]` 开头 |
| 密码 | 至少 6 位 |
| 标题 | 2–30 个字符 |
| 取件点/送达点 | 各 2–50 个字符 |
| 跑腿费 | 1–500 元，最多两位小数 |
| 超时时间 | 10–180 分钟，默认 60 |
| 评价 | 1–5 星，最多 100 字 |
| 充值 | 1–1000 元 |

## 项目范围

这个版本覆盖了浏览器工作台、从发布到评价的完整主链路，以及钱包、信用分、存证和管理统计。没有做的部分：

- 真实支付、短信通知、地图轨迹；
- 订单超时后的自动取消和退款；
- 签收、评价接口的幂等控制；
- 密码哈希、限流、审计日志；
- 多实例部署和消息队列。

这些在 README 的“当前版本边界”里也写了一遍，后续会按优先级补。
